### DSK-009 — shared session lease and safe terminal handoff preparation

- Added one atomic writable-session lease used by terminal, Web, and Runtime Pi
  processes. Ownership records include a nonce, canonical session path, PID,
  process-start identity, client interface, and heartbeat timestamps.
- A live or indeterminate owner fails closed. Stale recovery occurs only after
  the heartbeat timeout and a liveness check proves the recorded process is gone;
  malformed lock metadata is never silently replaced.
- Pi's public session lifecycle releases and reacquires ownership across quit,
  reload, new, resume, and fork. Explicit session switches are preflighted, and
  a startup race shuts down the losing Pi process before it can accept work.
- Added the authenticated Desktop-runtime `/terminal-handoff` contract. `open`
  returns a fixed workspace launch; `clone` creates an independent Pi session and
  restores Desktop to its original; `move` waits for graceful Pi disposal before
  returning the original session to the native shell.
- The launch response is always `coop` with either no arguments or one jailed
  `--session` path. The renderer cannot supply an executable, command, or argument.
- Native terminal application launch remains DSK-012. Checkout/worktree isolation
  remains DSK-018; this slice does not claim either is complete.
