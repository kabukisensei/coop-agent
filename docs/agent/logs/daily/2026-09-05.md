# 2026-09-05

## UX-003 — clipboard and attachment reliability

- Added one sandbox-compatible content-portability module used by Web and
  Desktop. It owns bounded text-file admission, likely-secret filename blocking,
  binary rejection, line-ending normalization, TSV generation, plain-text copy,
  and attachment wrapping/replay without acquiring filesystem or shell authority.
- Screenshot paste still intercepts only image clipboard items. Ordinary pasted
  SQL, DAX, YAML, JSON, and text retain native browser behavior and whitespace.
  Drag/drop intercepts only actual files. Selected files/images render before send
  with explicit removal, and a failed send restores the original message plus all
  attachments.
- Supported explicit text files are limited to five, 256 KiB each, and 768 KiB
  total. Likely credential/key filenames and NUL-containing content fail closed.
  The generated prompt suffix is versioned and length-delimited; replay consumes
  bodies by declared character counts so attachment content cannot forge filename
  metadata or hide user text.
- Added source-only copy for rendered code and Files previews, deterministic
  quoted-TSV table copy, and response-level plain-text copy. Button-copy output
  uses Windows CRLF where appropriate. Line-number gutters were removed from code
  previews, and native selected-text copying is deliberately not intercepted.
- Added a checked-in Windows interoperability evidence matrix covering SSMS,
  VS Code, Power BI-related editors, Teams, Chromium browsers, and Azure DevOps.
  Automated contracts are passing; application rows remain explicitly pending
  and block the Windows production gate when enabled rather than being inferred
  from macOS tests.
- Focused content-portability tests pass (six assertions), including malicious
  tag-shaped attachment content and fail-closed malformed replay. The authenticated
  Web bridge passes 270 integration checks, including the static allowlist,
  renderer authority boundary, copy controls, and native-selection contract.
- The complete Bash suite and PowerShell behavioral suite pass. The Bash run
  includes all 270 Web bridge checks and all existing launch, protocol, guardrail,
  review, Doctor, setup, session, extension, and diff regressions. PowerShell's
  UTF-8 BOM remains intact; parity and final diff gates pass. No install, commit,
  merge, publish, release, or installed Coop mutation occurred.

## REL-002 — signed update and rollback foundation

- Added strict versioned schemas for signed Desktop update descriptors, the
  app-pinned update trust registry, and the local active/previous activation
  record.
- Added a shell-neutral update service that verifies Ed25519 signatures over the
  exact manifest bytes, stable/beta policy, platform/architecture, issuance and
  expiry, HTTPS metadata, artifact size, and SHA-256. A signed key ID must resolve
  to an active app-pinned Ed25519 key whose lifetime, channel, artifact origin,
  and release-note origin authorize that descriptor. Unknown/revoked keys,
  unknown fields, credentialed URLs, symlinked artifacts, corrupt state, and
  store escapes fail closed.
- Update activation cannot run while Coop Runtime is live, cannot perform an
  ordinary downgrade, and requires named healthy evidence tied to the exact
  release ID and Coop/Desktop versions. Atomic activation retains exactly one
  prior verified version plus its key/artifact provenance; rollback is a separate
  health-gated operation and also requires runtime shutdown.
- Added a direct bounded downloader that rejects redirects and transport
  compression, writes an exclusive owner-only file, enforces size during the
  stream, fsyncs, verifies SHA-256, and deletes failed partials.
- Eight focused update tests pass on tampering, key identity/rotation policy,
  direct download cleanup, artifact verification, activation,
  rollback, and failure paths and are wired into both Bash and PowerShell runners.
  No production trust key, downloader, installer helper, signing, publication, or
  update execution has been added; those remain explicit release-authority gates.
- Added a fixed packaged-app trust loader. Development and unprovisioned
  packages report updates unavailable; a present malformed, revoked-only,
  symlinked, oversized, or external trust policy fails closed, and there is no
  environment/current-directory key fallback. Three focused loader tests pass.
- Enabled Electron embedded ASAR integrity plus only-load-from-ASAR and disabled
  Run-as-Node, Node options injection, CLI inspect arguments, and elevated
  `file://` privileges. Rebuilt the unsigned macOS arm64 app and directly read its
  fuse wire: every configured fuse matched. Production signing and the real
  in-ASAR public key remain absent by design.
- Added a native post-package verifier for macOS and Windows. It reads the actual
  Electron fuse wire, rejects loose `app/` and `default_app.asar` fallbacks, and
  runs complete managed-runtime manifest validation against the embedded bundle.
  The real macOS arm64 package passes; the manual managed build workflow runs the
  same verifier on both native workers. Three source/CI contract tests pass.
- Corrected and reran the managed-runtime verifier against a relocated real
  macOS arm64 bundle. The bundled runtime authenticated over loopback, reported
  exact Coop/Pi/Node/Python and companion-tool versions, kept credentials in the
  isolated smoke directory, and shut down cleanly.
