# dax-review — DAX, TMDL, and semantic model review tips
Run coop dax-review check . to lint DAX and semantic models.
Add --strict to coop dax-review in CI to enforce clean semantic models.
Pass --vpax model.vpax to coop dax-review check . for size-aware rules.
Use --write-baseline baseline.json to ratchet legacy DAX model issues.
Pass --baseline baseline.json to ignore existing technical debt.
Use // coop-dax-review:ignore <rule_id> inline in TMDL to silence a rule.
Run coop dax-review check . --format sarif -o review.sarif for code scanning.
Run coop dax-review check . --format html -o report.html for browser view.
Run coop dax-review check on TMDL folders, .bim files, or .pbit templates.
Run coop dax-review check . to catch unnecessary CALCULATE wrappers and risky iterators.
Run coop dax-review check . to flag context transitions inside iterator expressions.
Run coop dax-review check . to find bidirectional relationships across star schemas.
Run coop dax-review check . to flag missing or inconsistent measure format strings.
Run /semantic-model-review to get an architectural review of measures.
Use the tabular-editor-bpa skill to run Best Practice Analyzer rules.
Use --save-ignores to interactively save accepted findings in the config.
