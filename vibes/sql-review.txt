# sql-review — things to ask Coop about SQL quality and validation
Ask Coop to run its SQL review on this file, folder, or proposed change.
Ask Coop to explain each finding's rule, severity, and likely fix.
Try asking Coop to review only new findings against an existing baseline.
Ask Coop to check cross-file types and conversions with the available schema.
Ask Coop to flag SELECT *, unsafe writes, and grain-changing joins.
Try asking Coop to compare old and new review results before editing.
Ask Coop to prove a procedure refactor with exact before-and-after results.
Try server-side EXCEPT, counts, and aggregates for large output comparisons.
Ask Coop to poll warehouse procedure results until they are stable after execution.
Try a reconnect-safe baseline when DDL may invalidate the warehouse session.
Ask Coop to pre-aggregate facts independently before joining different grains.
Try asking Coop whether a many-to-many join explains inflated totals or timeouts.
Ask Coop to preserve a compatibility path while a replacement view is adopted.
Ask Coop to save important diagnostic SQL as a project file.
Try a small slice: backup, smallest change, SQL review, validation, then diff.
